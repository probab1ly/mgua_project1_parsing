# QA-аудит после внедрения Яндекс.Почты

Дата: 05.08.2026

## Executive Summary

Система email-рассылки переведена с Gmail на Яндекс.Почту. Конфигурация теперь использует `smtp.yandex.ru`, порт `465`, SSL, пароль приложения через переменную окружения. Пароль не хранится в `email_config.json`.

Рассылка логически уже встроена в процесс обновления: после завершения сбора данных приложение отправляет письмо с новыми материалами, а если новых материалов нет — письмо о выполненной проверке без новых находок.

Unit-тесты прошли: 20/20. API/security smoke прошёл. SMTP-тест без реального пароля корректно останавливается и показывает, какие поля не заполнены.

## Что проверено

- `python -m py_compile app.py scraper.py run_server.py quality_assurance/tools/smtp_test.py` — OK.
- `python -m unittest discover -s quality_assurance/tests -v` — 20/20 OK.
- `python quality_assurance/tools/smtp_test.py` без реального пароля — корректная ошибка незаполненных полей.
- `python quality_assurance/artifacts/yandex_email_api_smoke.py` — API/security smoke OK.
- Performance smoke:
  - 10 запросов: холодный старт, avg около 5441 ms из-за загрузки кэша.
  - 100 запросов: около 633 rps, p95 около 19 ms.
  - 1000 запросов: около 638 rps, p95 около 71 ms.

## Critical Bugs

Критических новых багов после внедрения Яндекс.Почты не найдено.

## High Bugs

### QA-YA-H-001. Реальная отправка не проверена без пароля приложения

- Категория: Functional / Email
- Критичность: High
- Шаги воспроизведения: запустить `python quality_assurance/tools/smtp_test.py` без `AI_MONITOR_SMTP_PASSWORD` и реального `smtp_username`.
- Ожидаемый результат: тестовая отправка письма проходит.
- Фактический результат: тест корректно останавливается: не заполнены `smtp_username`, `from_email`, `smtp_password`.
- Предполагаемая причина: настоящий Яндекс-логин и пароль приложения не внесены в `.env`/переменные хостинга.
- Рекомендации: создать пароль приложения в Яндекс ID, заменить `your-login@yandex.ru`, заполнить `AI_MONITOR_SMTP_PASSWORD`, повторить SMTP-тест.

### QA-YA-H-002. Нет ролей для управления рассылкой и обновлением

- Категория: Authorization
- Критичность: High
- Шаги воспроизведения: войти любым валидным пользователем и вызвать `/api/refresh`.
- Ожидаемый результат: запуск обновления и потенциальной email-рассылки доступен только администратору/оператору.
- Фактический результат: любой авторизованный пользователь может запускать обновление.
- Предполагаемая причина: текущая модель пользователей не содержит ролей.
- Рекомендации: добавить роли `viewer`, `operator`, `admin`; ограничить `/api/refresh`, `/api/history DELETE`, `/api/email/status`.

## Medium Bugs

### QA-YA-M-001. CSP всё ещё содержит `unsafe-inline`

- Категория: Security / XSS Defense
- Критичность: Medium
- Шаги воспроизведения: открыть `/login` или `/` и проверить `Content-Security-Policy`.
- Ожидаемый результат: CSP без `unsafe-inline`.
- Фактический результат: `unsafe-inline` присутствует.
- Предполагаемая причина: CSS/JS и inline handlers находятся в HTML.
- Рекомендации: вынести JS/CSS в `static/`, убрать inline `onclick`, затем ужесточить CSP.

### QA-YA-M-002. Холодный старт API медленный при параллельных запросах

- Категория: Performance
- Критичность: Medium
- Шаги воспроизведения: выполнить первые 10 параллельных запросов к `/api/articles`.
- Ожидаемый результат: стабильное время ответа.
- Фактический результат: холодный старт около 5.4 секунд avg; после прогрева p95 около 19-71 ms.
- Предполагаемая причина: ленивое чтение/синхронизация `cache.json`.
- Рекомендации: прогружать кэш до открытия порта; для production использовать persistent storage.

### QA-YA-M-003. Browser responsive audit не выполнен

- Категория: QA Process / UI
- Критичность: Medium
- Шаги воспроизведения: проверить наличие Playwright.
- Ожидаемый результат: можно прогнать 320/375/425/768/1024/1440/1920 px.
- Фактический результат: `ModuleNotFoundError: No module named 'playwright'`.
- Предполагаемая причина: Playwright не установлен в текущий Python.
- Рекомендации: добавить dev-зависимости для браузерных тестов или установить Playwright перед релизным UI-аудитом.

## Low Bugs

### QA-YA-L-001. SEO-функции минимальны

- Категория: SEO
- Критичность: Low
- Шаги воспроизведения: проверить `/robots.txt`, meta robots, sitemap.
- Ожидаемый результат: для публичного сайта есть sitemap/canonical/OpenGraph.
- Фактический результат: приложение закрыто от индексации, sitemap отсутствует.
- Предполагаемая причина: внутренний закрытый сервис.
- Рекомендации: оставить как есть для закрытого проекта; добавлять SEO только если сайт станет публичным.

### QA-YA-L-002. Analytics отсутствует

- Категория: Analytics
- Критичность: Low
- Шаги воспроизведения: поиск `gtag`, `ym(`, analytics scripts.
- Ожидаемый результат: если нужна статистика, события настроены.
- Фактический результат: аналитики нет.
- Предполагаемая причина: внутренний юридический инструмент.
- Рекомендации: для закрытого проекта допустимо; при эксплуатации добавить privacy-friendly серверные логи.

## Security Issues

- Положительно: пароль SMTP не хранится в `email_config.json`.
- Положительно: заглушка `your-login@yandex.ru` не считается валидной настройкой.
- Положительно: для Яндекса используется SSL-подключение через `SMTP_SSL`.
- Положительно: API без входа возвращает 401.
- Положительно: `/api/refresh` и `/api/history DELETE` требуют CSRF.
- Положительно: CORS не отражает внешний Origin.
- Остаточный риск: `unsafe-inline` в CSP.
- Остаточный риск: нет ролей.

## UX/UI Issues

- Блок email-статуса сообщает, если пароль/логин не заданы.
- История обновлений имеет кнопку очистки и внутренний скролл.
- Полный браузерный responsive-тест не выполнен из-за отсутствующего Playwright.

## Performance Issues

- Горячее API-поведение приемлемое для внутреннего сервиса.
- Парсинг внешних источников остаётся тяжёлой операцией; его нельзя запускать часто и параллельно.
- Для production лучше вынести парсинг в worker/очередь.

## SEO Issues

- `robots.txt` запрещает индексацию.
- `meta robots noindex` есть.
- Для закрытого проекта это корректно.

## Рекомендации перед релизом

1. Вписать реальную Яндекс.Почту в `email_config.json`.
2. Создать пароль приложения Яндекс.Почты и записать его только в `.env` или переменные хостинга.
3. Запустить `python quality_assurance/tools/smtp_test.py`.
4. Проверить `/api/email/status`: `ready=true`.
5. Запустить ручное обновление и проверить, что письмо пришло.
6. Добавить роли пользователей перед публичной эксплуатацией.
7. Установить Playwright/dev-зависимости и выполнить browser responsive-аудит.
